# 產品技術拆解方法

`methodology_version: product-technology-v1`

> **本檔的定位**：產品技術拆解的範圍、主線、來源效力、整合、生成、示意圖審查、限制與治理的**單一來源**。
> SKILL.md、README 與其他檔案一律**引用本檔**，不另抄一份變體。
> 本檔不依賴任何其他 skill 的檔案也能完整運作；提到其他 skill 之處都是交付格式或分工的對照。

## 一、定位與範圍

### 1.1 意圖

替投資人拆解一家公司**主力產品的技術細節**，讓讀者從高一層的角度看懂兩件事：

- **產品線怎麼跑**：產品從無到有，或是一次服務從頭到尾，經過哪些環節、每個環節做什麼。
- **供應鏈怎麼撐**：每個環節靠哪些設備、材料、軟體、基礎設施與廠商建起來。

這個 skill 比 Layer 1 小，但更專精。Layer 1（`business-industry-analysis`）回答「靠什麼賺錢」，
本 skill 回答「東西怎麼做出來、怎麼運作」。Layer 1 方法檔標為「屬技術報告範圍」的內容，歸本 skill。

### 1.2 目標

- 把「蒐集 → 整合 → 生成」三段流程寫成可重複執行的方法，三段各有明確的產出與關卡。
- 主要成品是**手機上閱讀的互動頁**，跟著產品的最小單位一步步播放。
- 每個說法都能追到來源，並標出來源層級。

### 1.3 非目標

- 不評價股價：沒有估值、目標價、報酬風險比、買賣判斷（與 Layer 1 相同）。
- 不分析商業模式與財務（屬 Layer 1）。營收占比、產能、研發投入這類數字只在說明技術地位時引用，
  例如新世代的量產爬坡、路線圖背後的投入規模；引用時只陳述數字，不做財務分析。
- 不做盲測。以實際報告驗收即可。

### 1.4 反目標

技術上做得出來，但算失敗的情況：

- 示意圖「看起來合理」但連接關係不成立：懸空端點、強調路徑經過不存在的線段、剖面前後步驟不連續、
  左右兩圖位置矛盾。台積電 N2 首例的第一版就犯了，而且通過兩輪「看不看得懂」的審查。對策是第六章：
  審查要逐條算座標，並附連接表。
- 來源效力不足，卻寫得像確定的事實。對策是第三章。
- 頁面只在桌機好看，手機上版面跑掉、細節看不見。對策是第六章第 7 條與第七章。

## 二、主線與兩條線

### 2.1 主線：跟著最小單位走一遍

報告的骨架是「有頭有尾」：從起點走到終點，前後連續，每一步都在前一步的結果上加東西。

- N2：跟著**一片晶圓**，從設計、光罩、做出電晶體、接上導線，走到測試與封裝。
- NET（Cloudflare）：跟著**一個網路請求**，從 DNS、Anycast、機房、DDoS、WAF、快取、Workers，走到經 Tunnel 回到源站。

### 2.2 兩條線：產品線與供應鏈都要

- N2 的製程步驟本身就是供應鏈，每一步都有對應的設備與材料廠商，兩條線重合。
- NET 的兩條線分開：請求的旅程說明**產品怎麼運作**；網路怎麼建起來（伺服器硬體、機房託管、頻寬與 ISP 互連）
  才是它的**供應鏈與成本結構**。

報告要把兩條線各自走完，並在交會處對上（例如「這一站的防護跑在哪種伺服器上、放在誰的機房」）。
兩條線在頁面上怎麼排（同一條時間軸分幕、或兩段旅程交叉索引）由實作者依該公司的形狀決定。

### 2.3 序幕與終章

- **序幕**：先講尺度或全貌，讓讀者知道接下來要走哪一段。
- **終章**：講演變與藍圖，包括世代、路線圖與競爭對手時程。

## 三、蒐集：來源效力

來源的效力是本 skill 最在意的一段：同一句話，來源不同，能說多強就不同。

### 3.1 來源分級

由高到低：

1. 公司正式文件：年報、SEC 或主管機關申報、法說會逐字稿、官網技術頁、新聞稿。
2. 公司技術文件：公司員工署名的論文、公司申請的專利。
3. 供應商或合作夥伴聲明。
4. 間接來源：不是這家公司寫的，但描述同類技術一般做法的學術資料或業界文件。
5. 媒體轉述。

分級看的是「這句話在講誰」：講其他公司自己的事（例如對手的量產時程）時，那家公司的文件比照上表判斷。
拿不準時標低一級。

### 3.2 引用規則

- 優先找第 1、2 級：官方文件、公司專利、公司論文。
- 引用專利時，寫成「公司申請過這種做法的專利」。專利證明公司在研究這個做法，不證明已用在量產產品。
  引用專利的先前技術段時，可以當作描述一般做法的第 4 級間接來源；引用實施例或請求項時，只能寫成「該公司申請過這種做法的專利」。
- 某一步在第 1 至 3 級都查不到時，用間接來源畫，並在頁面上明確標「間接來源」（N2 首例標為「業界通用」）。
- 不能當來源的清單見 3.3。
- 每份證據檔記逐字引文、來源網址、日期與分級。頁面上的摘要不得比逐字引文說得更強。
- 取 SEC 等要求聯絡資訊的資料源時，聯絡字串的來源依 `business-industry-analysis` SKILL.md「資料取得」的做法：
  唯一來源是環境變數 `SEC_USER_AGENT`。派 subagent 抓這類資料時，委派 prompt 要寫明聯絡字串的來源，
  否則 subagent 會拿使用者的 email 去填聯絡欄位。

### 3.3 不能當來源的清單

這份清單是全 skill 唯一的定義處，其他地方只引用這裡。新情況出現時擴充這份清單。

- 社群貼文
- 維基百科：可以拿來找條目引用的原始文件，引用時引那份原始文件

## 四、整合

### 4.1 依幕歸檔

證據依步驟（幕）歸檔，每一幕都要對得到證據檔：可以一幕一份，也可以相鄰幾幕合成一份，成品資料夾的 README
列出幕與證據檔的對照。廠商名單另一份。公司專屬資訊與業界通用資訊分開寫。

### 4.2 口徑並列

同一數字出現多種口徑時並列，寫明差異。例：N2 規格在 2022 至 2024 年間出現過三種口徑。

### 4.3 廠商標示

- ● 有公開資料顯示供貨或合作。
- ○ 該類主要廠商。

只列名字，可附股票代號，不加說明。

### 4.4 引用前對照

頁面引用前，對照證據檔的逐字引文，不只看摘要行。

### 4.5 逐幕獨立審查

每一幕交給獨立 agent 審查，審到「可發布」；步數少的相鄰幾幕可以合併成一次審查。每一輪都留審查紀錄，
與證據檔一起放進成品資料夾的 `research/`。

## 五、生成

**主要成品**：手機優先的互動頁，發布成 claude.ai 私人頁面。分幕、分步、分拍播放；左右兩張示意圖；
點材料或元件看說明；每一步列資料來源與相關廠商；有全螢幕沉浸模式。

### 5.1 互動頁資料格式

骨架是 `assets/walkthrough-skeleton.html`，內含兩幕三步的虛構示範內容。新頁面從骨架複製，
只改 `<script>` 開頭「資料」區塊的常數與 `buildScene()`；「引擎」區塊一般不改。
DOM id 沿用 N2，產生衍生成品的腳本依這些 id 擷取文字。`<script>` 放在 `.wrap` 之外。

#### 資料常數

| 常數 | 格式 | 用途 |
| --- | --- | --- |
| `META` | 物件，欄位見下表 | 頁首、頁尾與衍生成品的 front matter |
| `SRC` | `{ key: { t, label, url } }` | 來源清單；`t` 是 `TAG` 的 key |
| `TAG` | `{ key: { name, level } }` | 來源類型；`level` 是 3.1 的分級 |
| `SUP` | `{ 類別: { name, list: [[廠商, 'S' 或 'M']] } }` | 廠商名單；`S` 顯示 ●，`M` 顯示 ○（見 4.3） |
| `PARTS`、`PART_ORDER` | `{ id: { name, en, text } }`、id 陣列 | 圖中可點選的材料，與圖例的排列順序 |
| `SWATCH` | `{ 材料 id: CSS 變數名 }` | 圖例與材料說明的色塊（變數名不含 `--`） |
| `ACTS` | `[{ n, name, title, line }]` | 幕；`line` 是 `product`（產品線）、`supply`（供應鏈）或 `both` |
| `STEPS` | 陣列，欄位見下表 | 步驟與拍 |
| `STEP_SUP` | `{ 步號: [SUP 類別] }` | 每一步列出的廠商類別 |
| `buildScene(svgA, svgB, h)` | 函式 | 畫場景；`h` 提供 `el`、`R`、`T`、`C`、`card`、`photo` |

#### `TAG` 的 key

| key | 預設顯示 | 分級 |
| --- | --- | --- |
| `official` | 公司正式文件 | 1 |
| `paper` | 公司技術文件 | 2 |
| `vendor` | 供應商或合作夥伴聲明 | 3 |
| `generic` | 間接來源 | 4 |
| `media` | 媒體轉述 | 5 |

`name` 可以依研究對象改寫（N2 首例用「台積電官方」「論文」「廠商聲明」「業界通用」「媒體轉述」），
`level` 一律依 3.1 判斷。

#### `META` 欄位

| 欄位 | 用途 |
| --- | --- |
| `title`、`subtitle` | 報告標題與副標；`title` 也是頁首大標 |
| `subject` | 研究對象的公司名，用在廠商標示的說明句 |
| `supCaveat` | 選填；研究對象專屬的廠商但書，接在每一步廠商說明句的後面 |
| `market`、`ticker` | 市場與代號 |
| `type` | 固定為 `產品技術研究` |
| `methodology_version` | 固定為 `product-technology-v1` |
| `framework`、`date`、`version` | 研究框架、查證日、報告版本 |
| `footer_right`、`disclaimer` | 衍生成品的頁尾右側文字與免責聲明 |
| `readingGuide` | 字串陣列，衍生成品的「閱讀說明」：第一項是導言，其餘是條列 |
| `kpi` | `[{ label, value, note }]`，衍生成品的重點數字卡 |
| `actLead` | `{ 幕號: 導語 }`，衍生成品每一幕開頭的一句話 |
| `kicker`、`lede`、`notice` | 頁首的小標、導言與注意事項 |
| `footer` | 頁尾文字；來源類型的圖例由頁面自動接在後面 |

#### `STEPS` 欄位

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `n` | 是 | 步號（整數），也是網址 `#sN` |
| `act` | 是 | 所屬的幕號 |
| `title` | 是 | 步驟標題 |
| `label` | 否 | 取代「步驟 N／總數」的名稱，例如序幕、終章；總數只算沒有 `label` 的步驟 |
| `short` | 否 | 幕次軌道按鈕上的字，預設為步號 |
| `badges` | 否 | `TAG` key 陣列，顯示「含某類資料」徽章 |
| `cross` | 否 | 兩條線交會的步號陣列，顯示成「交會」標籤，點了跳到那一步 |
| `pa`、`pb` | 是 | 左圖、右圖標題 `[編號, 文字]`；寫在拍上時以拍為準 |
| `plain` | 是 | 這一步的白話說明 |
| `detail` | 否 | 細節段落的字串陣列 |
| `beats` | 是 | 拍的陣列：`{ now, a, b, pa, pb }`，`now` 必填，`a`、`b` 是左右圖說 |
| `sources` | 是 | `SRC` key 陣列 |
| `supNote` | 沒有列廠商時必填 | 不列廠商的說明 |

#### 場景

- 元件用 `el(svg, part, tag, attrs, on, off, fx, delay)` 畫；`T` 寫文字、`C` 畫不可點選的框線、`R(x, y, w, h)` 產生矩形屬性。
- `on`、`off` 寫成「步號.拍號」字串，拍號從 1 起；元件在 `on` 之後、`off` 之前顯示，`off` 留空表示一直顯示。一步最多 9 拍。
- `card(on, off, lines)` 在右圖畫一張文字卡。`photo(src, caption, on, off, url)` 在右圖放圖片，
  圖片載入失敗時改顯示一張卡片，寫出 `caption` 並附 `url` 的來源連結。
- 要交給連接檢查的元件只用 `<rect>`，並標 `id`、`data-net`（網路名稱）與 `data-kind`
  （`wire`、`via` 或 `node`，沒標時當作 `node`）。

**缺值**：必填欄位缺值時，畫面顯示空字串，console 留下「walkthrough：… 缺值」錯誤。頁面上不放佔位文字。

#### 對外介面 `window.walkthrough`

- `meta`、`steps`、`tags`：即 `META`、`STEPS`、`TAG`。
- `go(n, b)`：跳到步驟 `n` 的第 `b` 拍。`b` 是 `beats` 陣列的索引，從 0 起，比場景字串的拍號少 1。
- `setImmersive(on)`：開關全螢幕沉浸模式。
- `dumpScene()`：回傳目前顯示中、帶 `data-net` 的元件 `[{ id, svg, part, net, kind, x, y, w, h }]`。
  `svg` 是 `A` 或 `B`，座標是 `getBBox()` 的 viewBox 單位；`data-net` 標在 `<rect>` 以外的元素上時略過，並在 console 留錯誤。

### 5.2 衍生成品

- md 與 PDF 由互動頁逐拍截圖產生，符合 `research-report-output` 的「md 與 PDF 一律交付」。
- 改內容一律先改互動頁，再重產衍生成品。

重產流程是三步，在互動頁所在的環境裡跑（`<skill>` 指本 skill 的目錄，`<report-output>` 指
`research-report-output` 的 `scripts/`）：

```bash
# 1. 互動頁 → md ＋ 逐拍截圖（pdf-img/sNN-B.png）
python <skill>/scripts/build_walkthrough_md.py <互動頁.html> <成品資料夾> <md 檔名>
# 2. 數字密度檢查，要 0 命中
python <report-output>/fa_check.py <成品資料夾>/<md 檔名>
# 3. md → PDF
python <report-output>/md2pdf.py <成品資料夾>/<md 檔名>
```

- 第 1 步只讀互動頁上實際顯示的文字：front matter、閱讀說明、KPI、幕導語取自 `META`（見 5.1），
  廠商與來源徽章取自 `STEPS`、`SUP`、`SRC`、`TAG`。必填欄位或 `META` 欄位缺值時腳本直接停止，不產出 md。
- 截圖檔名的 `NN` 是兩位數步號，`B` 從 1 起算的拍號，與 md 的圖片連結一致。
- 第 2 步有命中時，回頭改互動頁的文字（把段落拆短），不改 md；改完從第 1 步重跑。
- 腳本依賴 Playwright（chromium）與同一個 plugin 內的 `research-report-output`；`md2pdf.py` 另需 pandoc。

## 六、示意圖審查

自繪示意圖發布前，由獨立 agent 審到「可發布」。審查要**逐條算座標**，並附連接表當證據：

1. 每段導線、通孔、連接線兩端都有接點；不同網路不交叉、不相碰（刻意示範時要有說明）。
2. 強調用的路徑或圈選，每段都疊在實際畫出的物件上，且圈到文字所說的東西。
3. 剖面圖材料層的上下順序、包覆關係正確；與前後步驟連續。
4. 同一物件在左右兩圖的位置一致。
5. 圖說、標籤、術語說明與圖一致；同一顏色在文字裡只用一個名稱。
6. 示範「錯誤狀態」時，錯誤畫在本身合法的物件上。
7. 手機寬度（375px）截圖下，關鍵細節看得出來。

### 6.1 連接表與檢查工具

畫線的示意圖元件（導線、通孔、節點）要標 `data-net`（網路名）與 `data-kind`（`wire`、`via` 或 `node`，省略視為 `node`），
而且只用 `<rect>`；其他標籤不會被傾印，工具會停下並指出被略過的元件。

- 要標的是實體連接：導線、通孔、接點、元件的接腳。流程圖的箭頭與連線由審查者依第 1、2 條人工核對。
- 剖面圖裡垂直於紙面的導線，畫出來是一塊截面，標 `node`；沿著紙面走的導線才標 `wire`。
- 刻意示範的違規（例如 DRC 示範的兩條線太近）工具會照樣回報，審查紀錄寫明是刻意示範、在哪一拍說明。

```bash
python scripts/schematic_topology.py <互動頁.html> [--step N --beat B]
```

工具逐拍切換場景，傾印顯示中的標註矩形，檢查四種問題：

| 問題 | 判準 |
| --- | --- |
| 懸空端點 | 導線的同網路接觸少於 2 個，或任一端超出最外側接觸點超過 `stub`（預設 2） |
| 短路 | 不同網路的兩元件距離 ≤ `tol`（預設 0.5） |
| 過近 | 不同網路的兩元件距離介於 `tol` 與 `near`（預設 6）之間 |
| 孤立通孔 | 通孔沒有碰到任何同網路元件 |

輸出是逐拍的連接表，欄位為 `| 元件 | 網路 | 接到 | 問題 |`，「接到」列出同網路接觸元件的 id。
exit code：1 是任一拍有問題；0 是沒有問題且至少一拍有標註元件；2 是受檢的拍都沒有標註元件，不算通過；
3 是用法或頁面錯誤。

審查者把連接表附在審查紀錄當輔助證據，上面七條仍逐條人工核對。`data-net` 是人標的，標錯時工具會把錯的連接驗成對的；
工具也只看矩形，不看斜線、曲線與文字。

## 七、限制

- 繁體中文（台灣）。數字與單位規範沿用 `research-report-output`。
- 瀏覽器自動化一律 headless。iPhone Safari 的版面差異 Playwright WebKit 測不出來
  （例如 WebKit 的 grid 內 `height:100%` 百分比高度），最後要使用者實機確認。
- 從 DOM 擷取文字用 `textContent` 並斷言非空；`innerText` 對收合的 `<details>` 與 `display:none` 回傳空字串而不報錯。
- 中間檔放在原始文件目錄，相對路徑圖片才不會變破圖。
- text-mode IO 一律寫 `encoding="utf-8"`。
- 表格欄數上限 7 欄。
- plugin 同時給 Claude Code 與 Codex 用；新 skill 要有 `agents/openai.yaml`。
