# 產品技術拆解

## 定位與分工

本 skill 回答「這家公司的主力產品怎麼做出來、怎麼運作，每個環節靠哪些設備、材料、軟體與廠商撐起來」，
**完全不評價股價**。範圍、主線、來源效力、整合、生成、示意圖審查、限制與治理的單一來源是
`references/product-technology-method.md`，本檔只做流程導覽。

- **商業模式與財務**屬 `business-industry-analysis`（Layer 1）。本 skill 填的是它標為「屬技術報告範圍」的內容。
- **md 與 PDF 的格式與交付**依 `research-report-output`；互動頁是主要成品，md 與 PDF 是它的衍生物。
- **估值**屬 `equity-valuation-discipline`（若有安裝），本 skill 的成品不含任何估值內容。

## 什麼請求走這裡

使用者要看懂一家公司主力產品的技術細節，或是產品線與供應鏈怎麼跑起來，就走這裡。
以技術為主體、需要逐步拆解的研究都適用；只問商業模式或營收來源的請求走 Layer 1。

## 工作流程

第一步之前，先讀 `references/product-technology-method.md` 第一、二章，確認範圍與主線。

1. 蒐集：依來源分級找證據，每份證據檔記逐字引文、網址、日期與分級：方法檔第三章
2. 整合：證據依幕歸檔、廠商另列、口徑並列，每幕交獨立 agent 審到可發布：方法檔第四章
3. 生成：互動頁為主，md 與 PDF 由互動頁衍生，成品放進成品資料夾：方法檔第五章
4. 示意圖發布前，由獨立 agent 逐條算座標審查，附連接表：方法檔第六章

來源的禁用清單見方法檔 3.3 節。

## 資料取得

- 一手資料：年報、SEC 或主管機關申報、法說會逐字稿、官網技術頁、新聞稿；公司員工署名的論文與公司申請的專利。
- SEC 文件全文與 `SEC_USER_AGENT` 的處理：見 `business-industry-analysis` SKILL.md「資料取得」。
  派 subagent 抓這類資料時，委派 prompt 要寫明聯絡字串的來源（方法檔 3.2 節）。
- 在第 1 至 3 級來源都查不到的步驟，標「間接來源」，不補成確定的事實：方法檔 3.1、3.2 節。

## Codex 端

Codex 只做蒐集與整合，生成互動頁、md、PDF 一律交給 Claude Code。

交接點：**每幕證據檔、廠商名單、每幕審查紀錄**三樣齊備就停，並告訴使用者改到 Claude Code 繼續生成。
Codex 端不產出互動頁、示意圖、md 或 PDF。

## 交付前檢查

逐項勾過才交付：

- [ ] 沒有估值、目標價、報酬風險比或買賣判斷
- [ ] 每個說法都標了來源層級，頁面上的摘要沒有比逐字引文說得更強
- [ ] 專利只寫成「公司申請過這種做法的專利」；查不到一手資料的步驟標了「間接來源」
- [ ] 同一數字的多種口徑已並列並寫明差異
- [ ] 每一幕都有獨立審查紀錄，審到可發布
- [ ] 示意圖通過方法檔第六章的七條審查，連接表已附
- [ ] 手機寬度（375px）截圖下關鍵細節看得出來，iPhone Safari 已請使用者實機確認
- [ ] md 與 PDF 由互動頁重產，內容與互動頁一致
