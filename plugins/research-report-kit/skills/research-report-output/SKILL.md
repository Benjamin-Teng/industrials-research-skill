# 研究報告輸出規範（md + PDF 雙檔）

## 職責邊界

本 skill 管**格式與交付**：長什麼樣、怎麼排版、怎麼產檔、怎麼交。

**內容標準**（估值方法、假設紀律、發布前的內容層檢查）交給 `/equity-valuation-discipline`；
**產業掃描與 channel check** 交給 `/product-cycle-rotation`；
**取價**交給 `/price-routing`。這三個都是可替換層——使用者若有自己的方法論文件，優先讀他的。

> **使用者方法論優先**：若使用者的 project／repo 中有自訂的研究框架文件（例如「個股深度研究框架」「投資決策手冊」），**那份文件是 source of truth**，本 plugin 的方法論 skill 退為預設值。設定方式見 `references/customize-your-framework.md`。

## 鐵則

1. 一律**同時產出 `.md` 與 `.pdf`**，PDF 由該 md 直接生成，不得手改。
2. PDF 一律用 `scripts/md2pdf.py` 產生（機構研究報告樣式）。
3. 兩檔都用 `SendUserFile` 交付，附一句話結論——不要複述報告內容。
4. md 必須有完整 YAML front matter（見下方樣板與 `references/output-spec.md` 第二章）。
5. 關鍵數據標**資料層級標籤**（`l1/l2/l3`）與**查價日**；價格書寫格式強制為「**數值＋日期＋盤別**」三件套（例：`US$218.98（2026-08-14 正常盤收盤）`），缺任一件即視為未查證數據。
6. **骨架不因市場而變**：台股、美股共用同一套章節與檢查清單，只換資料源與籌碼欄位（`references/market-localization.md`），依 front matter 的 `market` 取用。
7. 交付前跑完 `references/output-spec.md` 第八章的**格式層檢查清單**＋下方 **F-rules 六項自查（F-a 至 F-f）**；內容層檢查清單見 `/equity-valuation-discipline`。
8. **排版即內容**：任何需要讀第二次才能拆解的排版，等於沒寫。

## 可讀性格式規則 F1–F5（摘要）

> **總則**：每個小節的第一行必須能單獨回答「這節的結論是什麼」；推導、證據、來源一律排在結論之後，且一項一行。

| 規則 | 觸發 | 處理 |
|---|---|---|
| **F1 數據密集拆解** | 同一段落或**單一表格儲存格**出現 ≥3 個數字 | 拆成「一行結論 ＋ 實績表 ＋ 推導表」；表格內則拆為「**斷言欄**（一句結論）＋**數據明細欄**（每值一行、`<br>` 換行）」 |
| **F2 並列要點列表化** | 段落含 ≥2 個粗體行內小標，或涵蓋多個並列面向 | 轉列表；**粗體斷言先行**，補述接在 ` — ` 之後。無先後用 `-`，有因果用 `1. 2. 3.` |
| **F3 傳遞鏈視覺化** | 描述某變數如何經多環節影響標的 | 畫 ASCII 樹狀圖（節點格式：誰＋什麼影響＋`[+]`／`[-]`／`[~]`），下接摘要表 |
| **F4 結論前置** | 所有段落與 >3 行的表格 | 表格前必有 `>` blockquote 一句話摘要；h2 若直接開 h3，須先寫一行該節結論 |
| **F5 編號論點獨立化** | 段落出現 ①②③ 或行內編號 | 轉 markdown 有序列表；**不得用 ①②③ 當子節標題**（改 `### N.N`）。表格內的交叉引用標籤可例外 |

**F1 嚴重度分級**：🔴 ≥10 個數字必拆；🟠 6–9 拆（除非整段就是單句結論）；🟡 3–5 跨行則拆、單行結論句可容忍。

### 交付前 F-rules 自查

| # | 檢查項 | 判定細則 |
|---|---|---|
| F-a | 段落或**表格儲存格**含 ≥3 個數字？ | 依嚴重度分級處理；表格格內多值 → 拆出數據明細欄 |
| F-b | 段落含 ≥2 粗體小標？ | 遮蓋測試：遮掉一個 bold，剩餘仍是完整論點 → 須拆 |
| F-c | 有傳遞鏈／影響路徑描述？ | 套 F3 畫樹狀圖 |
| F-d | 所有 >3 行表格前有 blockquote？ | **含連續表的第 2、3 張；含 F3 圖後摘要表** |
| F-e | 殘留 ①②③？ | **含子節標題用法**；表格內交叉引用標籤例外 |
| F-f | h2／h3 首行是否為結論？ | **含 h2 直接開 h3 的情況**；清單型章節（來源清單、信號清單）首行即列表可接受 |

**完整的正反例、常見漏網區域與細則見 `references/formatting-rules.md`——寫報告前先讀一次，交付前再對一次自查表。**

## 工作流程

1. **先研究、後排版**：把資料查完、數字算完（估值模型以程式重算），再開始寫檔。研究階段不要碰產檔器。
2. **選骨架**：`templates/A-single-stock.md`（個股深度）／`B-industry-supplychain.md`（產業供應鏈）／`C-rotation-weekly.md`（輪動掃描週報）。
3. **命名**：`{主體}_{報告類型}_{版本}_{YYYYMMDD}.md`。版本語意：`v1.1` 補資料／**`v2.0` 結論改變**。同標的新版不覆蓋舊版。
4. **寫內容**：模板中標 `【TW】`／`【US】` 的欄位只留對應市場那一組。**寫完每一節立即檢查 F1–F5 觸發條件**，不要留到最後。
5. **產 PDF**：

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/research-report-output/scripts/md2pdf.py" 你的報告.md
   ```

   環境缺套件時：`pip install pypdf pyyaml --break-system-packages`（另需 `pandoc` 與 `playwright install chromium`）。依賴不全時的降級路徑見 `references/output-spec.md` 第六章。
6. **目視驗收**：

   ```bash
   pdftoppm -png -r 80 你的報告.pdf pg && ls pg*
   ```

   用 Read 看封面與最寬那張表所在頁，確認未溢出、頁碼正常。
7. **交付**：`SendUserFile` 送 md + pdf。
8. **歸檔**：報告本體不寫進知識庫（避免被單一標的長文灌爆）；只有方法論更新、可複用的產業地圖／觀察名單、覆盤結論才寫回。

### 取價

需要即時報價時，一律透過 **`/price-routing`** 決定取價工具與路徑，本 skill 不自行判斷市場路由。

## 輸出模式

報告有三種輸出模式；**預設為 Internal**，由使用者指示切換。

### Internal（自用，預設）

完整版——包含所有框架引用、方法論補充、規範版本聲明、自查表引用。命名用現行規則。

### External（傳播）

**刪除所有「內部模型」敘述，保留全部數據與結論。** 觸發：使用者說「給別人」「傳播」「第三方」「外部版」「external」。命名加 `_ext` 後綴。

須逐條掃描刪除：①框架標籤（`★A1`–`★A7`、`◇B1`–`◇B4` 及章節標題中的括號標註）；②框架引用句（「依框架 2.X」「規範第 N 章」「框架 vX.Y」）；③方法論補充段（改為直述結論）；④框架降級說明（改為直述理由）；⑤規範版本聲明；⑥自查清單引用；⑦強制處置的框架出處（保留處置本身）；⑧Caveats 中的方法論路徑描述（保留資料缺口本身）。

**保留**：所有數字、表格、結論、資料層級標籤、來源清單、KPI 卡、bull/bear/caveat 區塊內容本身。

### Briefing（摘要，≤3 頁）

結論速覽版，約 2,000–2,500 中文字。觸發：「briefing」「摘要」「重點速覽」「summary」「3 頁」。命名加 `_brief` 後綴。`type` 欄位後加「（Briefing）」。

**保留**：TL;DR（含 KPI 卡，刪推導表）、Key Findings（數據明細欄只留 1–2 項）、估值結論（只留情境表 ＋ Reverse DCF 一行）、Recommendations（評等 ＋ 加減碼訊號各前 2 項）、核心風險三點各一行。
**刪去**：市場共識拆解、事業結構全文、供應鏈全文（留一行定位句）、交叉驗證細節、敏感度矩陣（留排序第一名一句）、催化劑表、儀表板、Caveats 全文、來源清單。

### ⚠️ 刪節後處理（External 與 Briefing 共用）

刪除整節後**必須**執行以下三步，缺一視為未完成：

1. **章節重新編號**：刪掉「二」則三→二、四→三…連續遞減，不得跳號。
2. **子節重新編號**：原 `5.1`→`4.1`、`6.1`→`5.1`，與上層同步。
3. **交叉引用同步**：全文搜尋「第 N 節」「見 N.M」「回 N.M」「重跑 N.M」，一律更新為新編號；front matter 的 `note` 欄若引用節號亦須更新。

## Front matter 最小樣板

```yaml
---
title: 〈公司名〉〈代號〉個股深度研究報告
subtitle: 一句話講清楚論點與方法
type: 個股深度研究          # 個股深度研究 / 產業供應鏈研究 / 輪動掃描週報
market: TW                 # TW / US / TW+US
ticker: TWSE:0000          # 美股寫 NYSE:XXX、NASDAQ:XXXX
version: v1.0
date: 2026-08-06
price_asof: 2026-08-05 正常盤收盤     # 數值＋日期＋盤別三件套
author: 〈你的名字或機構〉
framework: 〈你的方法論文件名 vX.Y〉 ＋ 研究報告輸出規範 v2.0
rating: 〈分批布局／觀察／回避〉
footer_right: 〈頁尾右欄標語，預設「個人研究筆記 · 非投資建議」〉
disclaimer: 〈封面免責條款全文；不填則用預設值〉
baseline_of: 2026-08-13 Investor Day  # 選填；未來 30 天內有已排定事件、或事件已發生但結果未取得時必填
kpi:
  - {label: 現價, value: "NT$28.5", note: "2026-08-05 正常盤收盤"}
  - {label: 內在價值區間, value: "34–41", note: 三情境, tone: bull}
  - {label: 期望值 EV, value: "37", note: 機率加權}
  - {label: 熊情境下檔, value: "-18%", note: 論點失效時, tone: bear}
---
```

`tone` 可填 `bull`／`bear`／留空（中性）。KPI 卡 3–5 張，且數字須與內文一致。

## 專用語法速查

| 語法 | 效果 |
|---|---|
| `<span class="tag l1">公司揭露</span>` | 綠色徽章＝一手來源，可當基準假設 |
| `<span class="tag l2">分析師估算</span>` | 黃色徽章＝情境參考 |
| `<span class="tag l3">第二手</span>` | 紅色徽章＝**不得**納入基準假設 |
| `::: bull` … `:::` | 綠框：多方論點／實據端 |
| `::: bear` … `:::` | 紅框：空方論述／Pre-mortem／風險端 |
| `::: caveat` … `:::` | 黃框：資料限制與估算揭露 |
| `::: note` … `:::` | 藍框：一般提示 |
| `::: page` `:::` | 強制分頁 |

**表格欄數上限 7 欄**（超過請拆表），否則 PDF 會擠壓。估值三情境表常見 8–10 欄，須拆成「分母（營收×利潤率÷股數→EPS）」與「倍數與折現」兩張。

### 比較式內容雙色區塊

**觸發**：同一個 `::: caveat` 或 `::: note` 內含**對立主題**——「估算 vs 揭露」「短期利多 vs 長期風險」「自設假設 vs 外部來源」。

**處理**：拆成兩個顏色區塊，一面 `::: bull`（實據端）、對立面 `::: bear`（風險端），各自獨立標題。**顏色代表「方向對比」，不限於字面上的多空。**

**例外**：整段同方向的純資料限制聲明維持單一 `::: caveat`。
