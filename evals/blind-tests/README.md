# 盲測：規則增修的證據

`calibration-and-governance.md` 4.1 要求新增或修改規則時，附上案例或來源、回溯影響與半年檢驗條件。
盲測是取得這類證據的方法：讓不知情的 agent 拿不同版本的 skill 回答同一個問題，再依事先寫好的評分表計分。

本資料夾在 repo 根目錄，plugin 的打包範圍是 `plugins/research-report-kit/`，所以這裡的內容只隨 repo 版控。

## 檔案放在哪裡

一次測試一個資料夾，命名為 `YYYY-MM-DD-<主題>`，同名資料夾分成兩處：

| 位置 | 內容 | 版控 |
|---|---|---|
| `evals/blind-tests/<名稱>/README.md` | 測試問題、各版本對應的 commit、彙總結果、解讀與限制 | 進版控，公開 |
| `docs/blind-tests/<名稱>/` | 評分表、標準答案、受測輸出、計分檔與行號依據 | 維護者本機（`docs/` 已被 gitignore） |

原始資料留在本機，是因為受測情境與維護者的實際部位相關。公開的 README 只寫測試參數與彙總結果。

## 怎麼做一次盲測

1. **匯出 skill 副本**：用 `git archive <ref> plugins/research-report-kit` 匯出要比較的版本，刪掉
   `CHANGELOG.md` 與 `README.md`，因為變更紀錄會透露測試意圖。資料夾一律用中性名稱
   （`kit-a`、`kit-b`），並用 `grep` 確認副本裡沒有受測個股的名稱或關鍵數字。
2. **先寫評分表**：定義評分項目與 0–3 分的標準，寫好才開跑，避免看到結果再調整標準。
3. **受測 agent 只拿到使用者原話**：例如「我在考慮今天新建倉 XXX，你幫我快速判斷一下」。
   評分項目與測試目的只寫在評分表裡，讓受測 agent 照一般使用情境作答。快速判斷與完整報告各跑一次。
4. **鎖定時點**：回溯測試要寫明基準日，並規定發布日期晚於基準日的資訊一律不得使用。
5. **標準答案另派一個 agent**：它知道評分項目，負責依一手來源整理事實，另列「基準日之後」的資訊，供稽核時點洩漏。
6. **計分另派一個 agent**：它看不到 kit 內容，也不知道哪一組是新版本，只依評分表與標準答案計分，每一格都附行號。

受測 agent 的提示詞，沿用本次測試資料夾 `README.md` 裡的範本。

## 已知的坑

- **WebSearch 有每個 agent 的額度**，研究做到後段常會用完，信用評等這類項目因此被標成「未查」。
  計分時要把「額度用盡」和「規則沒要求」分開記，兩組 kit 的比較才公平。
- **擷取到的網頁常含基準日之後的資料**，受測 agent 自己也會揭露。計分時以 `response.md` 是否實際引用為準。
- **受測 agent 會用 `ls` 看到同層的其他輸出資料夾。** 每組輸出放在受測 agent 看不到的路徑，或在提示詞的禁止清單列出「列出其他資料夾」。
- **每組只跑一次（n=1）**，只能看方向，不能當統計證據。
