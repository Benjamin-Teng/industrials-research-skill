# 2026-10-11 建倉／加碼前的資產負債表檢查

## 測試問題

1. 沒有被提示的 agent 拿到 skill、被問「能不能新建倉或加碼」，能不能自己找出資產負債表上的風險，
   並讓這些風險進入決策理由？
2. PR #3 提出的「建倉前快篩」，以及取代它的 v1.5.0「最低檢查＋決策段回應警示」，比改版前好在哪裡、
   有沒有誤報？

原始資料（評分表、標準答案、受測輸出、計分檔）在維護者本機的 `docs/blind-tests/2026-10-11-pre-entry-check/`。

## 評分方式

六個評分項目：K1 財務槓桿與到期結構、K2 表外承諾、K3 資本支出資金缺口、K4 信用訊號、
K5 控股股東或董監質押、K6 控股股東或家族層級的擔保與相關交易。

- 每家公司先依標準答案，把六項各自歸為「存在且重大」「存在但不重大」或「不存在」。
- 「存在且重大」的項目給 0–3 分：0 沒提及；1 提及但沒判為風險，或標「未查」；2 判為風險並附來源；
  3 進一步進入情境或決策理由。
- 其餘項目記「誤報」或「正確」。
- 「額度」表示受測 agent 的搜尋額度用盡，該項沒有查到。

## 解讀

- **改版前的規則多數抓得到，缺口有三處。** 快速判斷不跑財務品質檢核；美股沒有質押的查核來源；
  警示沒有進入決策理由。v1.5.0 針對這三處修改，三處都在盲測中看到改善。
- **三個版本、六份 ORCL 輸出的結論都是 `watch`。** 規則改變的是決策理由與揭露，沒有改變結論。
- **PR #3 的 24 個月承諾口徑偵測力較弱。** 同一批在三年內陸續起租的租約，24 個月口徑只得營收
  17.4%；改版前的總額口徑則為營收的數倍並觸發警示。
- **K6（控股股東家族擔保）在所有版本都只拿到 0–1 分。** 標準答案也指出，它和上市公司股票的連動
  只見媒體推測，所以列入觀察區，不修法。

## 限制

- 每組只跑一次（n=1），受測模型是 sonnet，只能看方向。
- ORCL 是促成這次修改的案例，屬樣本內測試；AMD、CHTR 才是樣本外測試。
- 受測 agent 的搜尋額度常在後段用完，CHTR 的 K4 因此在所有版本都只拿 1 分，無法比較。
- AMD 的 K2 是否「重大」，由標準答案 agent 以自訂門檻判斷，計分 agent 依評分表沿用。
- 第一輪計分檔開頭的「計分操作化」一節，是計分 agent 開跑後補的細則，評分表本身在開跑前寫定。
- 第二輪有一份受測輸出用 `ls` 列過同層資料夾名稱，沒有開啟其中的檔案。
- 最終版的文字修正沒有重跑盲測。

## 受測提示詞範本

快速判斷與完整報告只差在「使用者的請求」一段。路徑、日期與情境依測試調整。

```text
【角色】你是使用者的投資研究助理。使用者裝了一組研究用 skill（plugin），檔案放在：
<kit>\skills\
範例報告放在同一層的 examples\ 資料夾。

【怎麼使用 skill】照一般 skill 觸發的方式來：
1. 先讀 skills\ 下每個 SKILL.md 開頭 frontmatter 的 description，判斷使用者這個請求該用哪些 skill。
2. 選定以後讀那份 SKILL.md 全文，再依它的指示去讀需要的 references、templates，照著執行。
skill 沒要求的事不用額外做，skill 要求的事都要做到。唯一例外：不必產 PDF，Markdown 就夠。

【時間設定】今天是 <基準日>。只用基準日當天或更早已公開的資訊；發布日期晚於基準日的資訊
一律不用；查不到發布日期的標「日期不明」。

【使用者狀況】使用者不在線。需要使用者資訊時（例如風險政策、持有期），依 skill 的規則標
unknown／unspecified 或提暫定值，然後繼續完成。

【使用者的請求（原文）】
快速：「我在考慮今天新建倉 <代號>，你幫我快速判斷一下，現在能不能買？」
完整：「我在考慮今天新建倉 <代號>。請幫我做一份完整的個股研究報告，最後告訴我能不能建倉。」
加碼情境把「新建倉」改成「加碼」，並註明使用者已持有。

【產出】
1. 給使用者的完整回覆寫到 <out>\response.md。
2. 同目錄的 process-log.md：讀過的 skill 檔、依序執行的步驟與跳過的理由、來源清單（URL、發布日期、用途）。
3. 最終訊息不超過 15 行：兩個檔案的路徑，加上給使用者的最終建議一句話。

【禁止】以下動作一律不做：
- 讀取或列出 <kit> 以外的檔案與資料夾
- 執行 git
- 修改 <kit> 內的檔案
- 安裝套件
```
