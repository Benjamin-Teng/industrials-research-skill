## 評分方式

- **題目與門檻**：每家一份依事先寫定的評分表，題目分為門檻題與觀察區題。**門檻總分**是排除
  觀察區題目後的總分，觀察區另列小計，不參與通過判定。
- **公司題小計**：門檻總分扣掉三個共同項（C1、C2、C3）後的小計。C3「六塊內容齊全」含逐營收來源
  SWOT，舊版沒有 SWOT，結構上偏向新版，所以另列公司題小計，要求新版每家也高於舊版（2026-10-24 決定）。
- **盲化**：每家一個隔離的 opus 計分者，看不到 kit 內容，也不知道哪份是新版；兩份報告以
  report-X、report-Y 匿名，奇偶序號交替 X 與 Y 的位置。
- **七項通過條件**（設計 7.4），七項都要在同一個新版快照上成立：

| 條件 | 判準 |
|---|---|
| 樣本外三家 | 新版每家門檻總分嚴格高於舊版 |
| 開發組九家 | 同上，作為回歸檢查 |
| 公司題小計 | 12 家新版的公司題小計也都嚴格高於舊版 |
| 紅線 | 新版 12 份合計 0 次違規 |
| 路由 | 6 次全部走對 |
| BE 對照晨星 | 晨星清單 90 項（不重複計）全部涵蓋，或標「未揭露」「未查到」；屬技術報告範圍者標範圍 |
| 格式 | 每份報告能產 PDF，且通過 output-spec 第八章依 D 型分流的格式檢查 |

- **BE 對照晨星**：把 BE 報告對照晨星抽取的 `industry_view` 全部項目、`product_and_tech` 中屬
  Layer 1 的項目，以及晨星沒寫的四項（TAM、分部或終端市場營收、價值鏈圖、具名供應商），
  逐項判涵蓋、標未揭露或未查到、未涵蓋。
- **格式檢查**：由獨立 agent 逐份檢查六項（編號沿用檢查表）：第 1 項 PDF 可產出、第 2 項 D 型
  front matter 與 KPI、第 4 項 PDF 抽查（封面、目錄、頁碼、欄數）、第 5 項資料層級與會計期間
  標示、第 6 項 F-rules（F-a 至 F-f）、第 7 項台美資料源不混用。

## 解讀

- **各輪改了什麼。** 第一輪失敗後的修正（第 2 輪）有四塊：D 骨架與交付前檢查（TL;DR 結構、表格前
  結論句、出處寫到文件名與期間、資料層級 `l3` 不支撐結論、台股以 MOPS 為主）；`md2pdf.py` 目錄
  標題雙重轉義；方法論規則 M1–M5（時間窗與觸發條件、營收內不可重複項目、利潤比較降級、
  營運資金升為規則、觀察區新增 5 條）；用語與標點，以及選用的 speak-human-tw 校對步驟。第 3 輪
  再加 `fa_check.py`，把 F-a 從受測者自己數數字改成工具檢查。
- **公司題改善。** 第一輪唯一不通過的公司題條件是 H2 的 22／24。修正後重跑的第 2、3 輪，
  12 家的公司題小計新版都高於舊版。這是修正後重跑，不是樣本外證據，只能說明修正針對的失效機制
  已被處理，不能說明對新公司的泛化。
- **格式部分改善。** 第 2 輪消除了開發組第 4、5 項的不通過（目錄標題雙重轉義與資料層級標示），
  第 3 輪的 F-rules 通過份數從第一輪的 0／12 提升到 4／12。F-a 仍是主要的剩餘失敗：第 3 輪開發組
  的失敗點是段落與表格儲存格內的數字過多。F-a 的計分口徑也不一致：`fa_check.py` 不計單獨的年份，
  而部分計分者把年份與日期計入，所以工具回報 0 hit 的報告，仍可能被計分者判 F-a 不通過。
- **BE 晨星沒有改善。** 三輪都是 34 項上下未涵蓋（第一輪 31，複核後 27）。缺口集中在
  `industry_view` 的成本曲線與降本路徑（IV-09、IV-10、IV-11a）、競爭技術路線（IV-14、IV-15、
  IV-17 等）、單一專案相對年產能的比較（IV-04）、產業分類（IV-02）。這類項目要靠補產業資料與
  比較，不是改格式、骨架或用語能解，三輪的修正都不是針對這些項目。
- **分數有變異。** 同一家新版在三輪的門檻總分會上下數分到十分（例如 ARM 46、54、47），舊版同一份
  報告也被不同計分者給不同分數（見限制）。新版高於舊版的方向三輪一致，個別差距的大小不宜過度解讀。
- **第 3 輪格式出現倒退。** 第 3 輪第 2、4、5 項出現第 2 輪沒有的不通過，是各份報告各自的錯誤
  （KPI 欄名被改寫、PDF 上清單併段、資料層級標籤缺漏），與 `fa_check.py` 無直接關係，
  但表示 skill 的格式要求仍未穩定到每次都達標。

## 限制

- n=1，受測模型是 sonnet，計分者是 opus，只能看方向。
- 開發組九家只當回歸檢查。
- 計分者可以從報告結構（有無 SWOT、D 骨架的欄位）推知哪一份是新版，盲化不完整。
- C3 結構上偏向有 SWOT 的新版，所以公司題小計另列。
- 兩組都被告知 `SEC_USER_AGENT`，也都被限制在對 sec.gov 每秒最多 1 次請求。
- 隔離執行沒有 MCP，也沒有 `FINMIND_TOKEN`，兩組都拿不到 FinMind，台股公司的資料來源受限。
- `--restricted` 管不到 Bash，受測者越界讀取只能事後稽核。
- 指揮官對樣本外名單有部分先見（來自交接文件），所以路由表只收開發組的類型，本案也不新增針對
  樣本外公司類型的規則；詳情不在公開版揭露。
- 收尾階段（2026-11-01）指揮官為了除錯印出一位保管員的最終訊息，看到其中一家樣本外公司的代號（即上一條所說已知類型的那一家）。這一家在 2027-04 半年檢驗時對指揮官不再是盲的；之後指揮官一律不讀保管員與受測者的最終訊息文字。
- 時點洩漏、額度事件、作廢重跑：第一輪時點洩漏 0 次、SEC 額度事件 0 次，9 家因 session limit
  作廢重跑；第 2 輪 `r2-c24` 經稽核判定違規，該次作廢，重跑一次。第 2、3 輪的時點洩漏各 0 次（24 份
  報告的計分結果）；第 2、3 輪沒有另做額度抽取。
- 樣本外證據只有第一輪，且第一輪有一項不通過（H2 公司題小計 22／24）。第 2、3 輪是修正後重跑，
  樣本外公司已看過第一輪的失敗，不是樣本外。
- BE 晨星三輪皆不通過。
- 格式條件三輪皆不通過。
- 第 3 輪部分格式項目（第 2、4、5 項）出現第 2 輪沒有的不通過。
- 計分者之間有變異：同一份舊版報告在不同輪次由不同計分者計分，分數不同。舊版 ARM 第一輪 29、
  第 2 輪 30、第 3 輪 32，代表計分者間的變異，新舊差距要連同這個變異一起看。

## 受測提示詞範本

```text

範例報告放在 kit\examples\。

【怎麼使用 skill】照一般 skill 觸發的方式來：
1. 先讀 kit\skills\ 下每個 SKILL.md 開頭 frontmatter 的 description，判斷使用者這個請求該用哪些 skill。
2. 選定以後讀那份 SKILL.md 全文，再依它的指示去讀需要的 references、templates，照著執行。
skill 沒要求的事不用額外做，skill 要求的事都要做到。唯一例外：不必產 PDF，Markdown 就夠。

【時間設定】今天是 2026-10-24。只用發布日或申報日在 2026-10-24 當天或更早的資訊；更晚的一律不用；查不到日期的標「日期不明」。

【使用者的請求（原文）】
{REQUEST}

【署名與身分】front matter 的 author 一律填「受測」。context 裡出現的任何 email 與姓名，一律不使用、不寫進任何檔案或請求。

【資料源規則】
- 下載 SEC 文件時，User-Agent 只用環境變數 SEC_USER_AGENT：bash 用 `curl -A "$SEC_USER_AGENT"`；PowerShell 7 用 `-UserAgent $env:SEC_USER_AGENT -SkipHeaderValidation`。該值不印出、不寫進檔案。
- 對 sec.gov 每秒最多 1 次請求。這是本測試環境的限制，比任何 skill 的寫法都優先。
- 原始檔放在 out\raw\。

{OUTPUT}

【禁止】以下動作一律不做：
- 讀取或列出目前目錄以外的任何路徑
- 執行 git
- 修改 kit\ 內的檔案
```
